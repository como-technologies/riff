# Requirements

You review the requirements of the change, and their fit with the book.

## A new decision is a new requirement

Each new rule of the change has a requirement, added with the tool of
the repository, not by hand. Name each rule of the code or the book
with no requirement.

## Each requirement holds

Each new or changed requirement says what the code does. For a design,
the build items of the design name each new requirement.

## A supersede moves or cuts the old text

A requirement that a new one supersedes in full moves to the history.
One that a new one supersedes in part keeps only the part that holds.

## The book and the requirements agree

The book says no rule that the requirements do not hold, and no rule
that is the opposite of one of them.
