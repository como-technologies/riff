# Review link-02: the implementer

Issue: #420. Design at commit 56091d2. Code of today at commit a67f384, and the #424 branch `origin/worktree-issue-424` (PR #491).

## Summary

The design fits the code of today in most parts: `send_with`, `follow`, the stream client with no pool, the build check and the outage rule are there, and the link is a change of form. Three parts cannot start as written. First, the client speaks HTTP/2 to Cloud Run, so "drop the pool" and "a connection of its own" need concrete rules in reqwest terms. Second, the kept reply of section 3 is made in the future of the call, which axum drops at a cut: that is the case that the kept reply is for. Third, the code `repeat` gives "a reply with no body", but each typed reply (`ClaimReply`, `Posted`, `ReleaseReply`) needs a body. The budgets per process also break `riff mcp` tools, `chat` and `top`. I read the code and the sources of reqwest 0.13.5, hyper-util 0.1.21 and axum 0.8.9 in the cargo registry. I built nothing.

| link-02-1 | The client speaks HTTP/2 to Cloud Run. ## The questions of this point of view

### Can each build item start with no question?

- L1: no, not yet. It needs link-02-1, 02-3, 02-9, 02-10, 02-11, 02-12 and the table of section 7.
- L2: yes, with link-02-17.
- L3: yes, with link-02-13, 02-14 and 02-15.
- L4: no. It needs link-02-4 to 02-8. The design of section 3 does not work with `dispatch` of today.
- L5: yes after #491, with link-02-16.

### Does the client speak HTTP/2 to Cloud Run?

Yes, by ALPN, from the default features of reqwest 0.13. The calls share one connection. Each stream has its own, because its client has no pool. See link-02-1 and link-02-2.

### What does `KeepAlive::default()` give?

A comment each 15 s, when no event went in that time. With the `: ready` comment, a live stream never has 45 s with no byte. So `STREAM_IDLE` 45 s is right: it is three missed comments.

## Questions for the lead

- Is a header `riff-call` fine in place of the body field `call` (link-02-8)? It changes the text "The wire" of section 3.
- May the reply to a repeated call show the state of now, not the state at the first try (link-02-4, 02-6)? For a claim that another session took between the tries, it says "held by", not "granted".
- Does `HOOK_BUDGET` replace `STATE_WAIT` 3 s, or does R69 keep 3 s (link-02-11)?
